# Connection hardening checkpoint (2026-11-19)

Nine-loop hardening pass over `src/backend.rs` transport. Branch `feat/loop-improvements`, commits `d6343fe`, `673081b`, `d3339ea`, `8961aa2`, `a1ccb8f`, `b981833`, `f788aab`, `7414196`, `424ef1e`.

## Durable decisions

1. **Automatic reconnect**: exponential backoff 1s, 2s, 4s, 8s, 16s, then 30s cap (`reconnect_delay`), reset on success (`reconnect_deadline`). Authentication rejections (login 401/404/429, ticket 401, scheme failure) set `Link.retryable = false` and are never auto-retried — a bad password must not hammer the login endpoint. Auth failure is the ONLY non-retryable class; network/ticket/HTTP failures stay retryable.
2. **A Reconnect press mid-sign-in aborts the in-flight attempt** (`open_link` loops on `OpenStop::Restart`); leaving the select block drops the pinned `connect()` future, which cancels its HTTP requests and socket dial. Dispatch via pure `mid_connect` (Queue/Restart/Shutdown).
3. **Idle keepalive is RFC 6455 Ping** after `PROBE_SILENCE` (30s) without any inbound frame; Pong refreshes `last_inbound`. A healthy idle connection is no longer dropped by the silence rule. `SILENCE_BOUND` (90s) is deliberately ≥ `COMPRESS_TIMEOUT` because a server-side compress may push no intermediate frames — do not tighten it to "speed up dead-link detection" without revisiting compress.
4. **Socket writes are bounded by `WRITE_TIMEOUT` (5s)**, far below the 30s RPC response wait: a gateway that stops reading fails the write in 5s and auto-reconnect takes over. tokio-tungstenite `connect_async` already sets TCP nodelay (verified in vendored source), so no Nagle workaround is needed.
5. **Streaming deltas never block the transport loop**: `emit_delta` uses `try_send` with a per-runtime pending tail capped at `DELTA_TAIL_CAP` (1 MB, UTF-8 boundary trim via `trim_to_cap`), retried each 5s maintenance tick; rollover drops the old tail (never concatenates out of order); `MessageComplete` supersedes parked tails (it carries authoritative text); `close_socket` clears them. The bounded event channel (`EVENT_BOUND` 512) stays bounded.
6. **On `gateway.ready`, queued commands drain BEFORE the studio catalog fetch**, and the two catalog HTTP requests run concurrently (`tokio::join!`); post-reconnect time-to-interactive does not wait on catalog RTTs. The UI's `note_connection` re-lists sessions and re-resumes the selected one on every Connected event, so auto-reconnect restores context end-to-end.
7. **Handshake decomposition** (`sign_in`, `request_ticket`, `ws_dial_url`, `dial_socket`), supervision decomposition (`fail_expired_jobs`, `heartbeat_ping`, `flush_pending_deltas`, `probe_keepalive`): backend.rs has zero baselined complexity hotspots; the guardrails complexity baseline is 4 entries and exactly matches the live CCN>10 warnings.
8. **No HTTP call and no work-result application crosses a connection boundary** (`b5cdc77`): every off-loop task delivers through a `WorkSink` (work channel + connection epoch bound together; the plain sender type never reaches a task signature, so the stamp cannot be forgotten), `close_socket` bumps `epoch` on every teardown, and `run()`'s dispatch drops results whose epoch no longer matches. A fetch racing a disconnect can therefore never adopt a turn for a dead runtime or surface a stale failure. Audits taught twice that "closed" claims must be grep-mechanical; the epoch guard makes the remaining class (spawn/deliver across teardown) impossible by construction.
9. **One honest failure rule for both not-yet-connected states** (`78d4de6`): commands arriving mid-dial classify through the same `is_queueable_while_connecting` allowlist as `handle_unready_command` — the five replay-safe commands (list/create/resume/search/studio fetch) queue; everything else becomes `MidConnect::Reject` and is emitted through the shared `reject_unready` mapping ("Not connected. Reconnect to try again."), never replayed against runtime ids from the torn-down connection. On a stuck dial the rejection lands when the attempt resolves (bounded by the 90s connect bound; a Reconnect press breaks the dial immediately).
10. **Deferred curation is serialized and surfaced, never silent** (`c86e82c`): a session has at most one patch in flight (per-session `patching` set); a colliding mutation rides the deferral (`absorb_into_deferral`) and flushes when the in-flight patch applies (`chain_deferred_flush`, success-only chaining — a permanent 404 must not loop per round trip). The deferred flush re-enters via `LoopWork::Deferred`: gateway refusals re-defer and surface as curation errors; transport failures re-defer quietly for the next message. `reinsert_deferred` MERGES, never overwrites: intent absorbed during the in-flight window is the user's later values and wins.
11. **Equal jitter on the reconnect backoff** (`50318cd`): each attempt lands in [half, full] of its scheduled delay (`jittered` + `jitter_subsec`, wall-clock sub-second nanos — vDSO-cheap, only has to desynchronize, not a randomness source). `reconnect_delay` stays pure; `reconnect_deadline` takes the sampled subsec, keeping the seam deterministic for tests.
12. **Delta frames decode without the JSON DOM** (`1af86a8`): `delta_frame_fields` parses a borrowed serde envelope (`#[serde(borrow)]`) behind a `text.contains("\"message.delta\"")` needle pre-filter — every other frame keeps its single full `Value` parse; a literal needle inside a payload falls through to the envelope check and the unchanged route. Fast path and DOM fallback share one state machine (`on_delta_fields`), and `emit_delta` takes a `get_mut` fast path before `entry` so steady streaming allocates no map key.
13. **Steady delta frames allocate the text buffer only** (`f72b2c0`): `Event::MessageDelta` ids are `Arc<str>`, the pending-delta entry carries the shared ids and survives successful sends (empty-tail guards in `try_flush_delta` and the rollover path keep event semantics identical; `MessageComplete` and `close_socket` still clear the map), and `ensure_turn` no longer rewrites the turn id when it already matches — a hidden per-frame allocation the String version also paid. Keeping-up frames dropped 7 → 1 allocations (the delta buffer), parked 5 → 1, sustained parking 0 once the restored tail has room. A counting-global-allocator test pins the budget (cold 5, steady 1, parked 1) on a thread-local counter so parallel tests cannot pollute it; the UI takes the id by reference, so no per-token string is built there either.
14. **Dial bound independent of the RPC wait** (`97963a9`): the WebSocket handshake (TCP + TLS + upgrade) carries a dedicated 10s `DIAL_TIMEOUT` instead of borrowing the 30s `RPC_TIMEOUT`. A wedged/black-holed gateway that accepts but never completes the upgrade fails each dial in 10s; the reconnect backoff reaches its next attempt ~20s sooner. HTTP sign-in/ticket keep the 30s RPC timeout (slow-but-real logins on poor links must not false-fail); 10s is generous for a pure transport handshake against a LAN/tunnel gateway. Pinned by `wedged_socket_dial_aborts_at_the_dial_bound` (accepting-but-silent listener; asserts ≥ 9s and < 30s plus the Disconnected event).
15. **Streaming renders one row, not the transcript**: `Conversation.stream_revision` bumps only on in-place appends to the trailing message (`append_delta` push_str branch); the coarse `revision` moves on new rows, completion (gate flips), and everything structural. `sync_message_list` treats a stream-only change as a single-row splice via `trailing_row_update` (walks back the contiguous assistant/tool fold run, builds that row with the same gates/targets/find state as a full rebuild; equivalence pinned by `trailing_row_update_matches_full_rebuild_for_every_fold_shape`). Previously every 60ms batch rebuilt all rows (`ChatMessage::clone` per message) and `PartialEq`-compared the whole transcript to reach the one row that changed — O(transcript) per batch during streaming. Finish_message keeps its conservative coarse bump (busy-gate flip must re-render all rows).
16. **Login-session expiry is transient; a rejected password is not**: REST helpers share a per-task `AuthSignal` trip flag (`WorkSink.auth`), set on any HTTP 401. The task reports unit `LoopWork::AuthRejected`; `apply_auth_rejected` tears a live socket down once (`auth_reject_seen` + `write.is_some()` guard), the reconnect re-runs `sign_in`, and the flag resets there on success. Rationale: the WS rides a connect-time ticket while REST rides the login cookie — a cookie TTL or gateway restart used to wedge every list/history/search/upload/patch with permanent-looking errors until app restart, while the fix path already existed (reconnect's sign-in). Deliberately NOT: re-login inside each task (credential plumbing into 12+ task signatures, and N concurrent 401s could stampede the login endpoint into a real 429 lockout — the same 429 that marks auth permanent). Pinned by `unauthorized_rest_trips_the_auth_signal` (helper level) and `expired_login_session_tears_down_once` (task → work → apply, dedup, stale-guard). Tests fabricate a real socket via `WebSocketStream::from_raw_socket` over a plain loopback TcpStream (no WS server needed).
17. **Socket writes never run on the transport loop** (`writer_task` + `LoopWork::WriteDead`): a background writer owns the `SplitSink` for one connection; the loop holds only an unbounded `WriteTx` queue (same never-blocks precedent as `LoopWork`), so wedged-socket backpressure costs frame processing nothing (was: up to 5s stall per write on-loop, bursts serialized 5s×N). The writer applies frames in order inside `WRITE_TIMEOUT` (5s; test-injectable so wedge tests run in ms), reports one dead link on the captured epoch, and exits; the stale-guarded `apply_write_dead` does the teardown (one disconnect + `fail_jobs`). Rationale for channel-report instead of inline teardown in `send_raw`/Pong/probe: a closed-channel path calling `drop_socket` → `fail_jobs` → `on_rpc_error` → `send_raw` closed a static async-recursion cycle (E0733); the work arm is the single teardown point. In-flight jobs now fail immediately with the disconnect instead of waiting out 30s RPC deadlines. Tests: duplex-backed WS with no reader pins WriteDead-at-bound; drained duplex pins ordered flush + clean exit (drop the retained read half before awaiting the drainer or EOF never arrives); apply-level pins teardown-once + job failure.

18. **Every connect step is bounded at its own latency class** (`SIGN_IN_TIMEOUT` 10s): the password login and ticket requests carry a per-request 10s reqwest timeout, not the client-wide 30s RPC bound — the dial's 10s `DIAL_TIMEOUT` precedent applied to the auth leg. Rationale: a wedged/black-holed gateway burned 30s+30s per reconnect attempt before the backoff could retry; auth is a pure round-trip against a LAN/tunnel gateway where >10s is pathological, and failing fast trips the backoff cycle 3× sooner. The 90s `CONNECT_TIMEOUT` stays only as the outer safety net; error strings and retryability are unchanged (transport timeouts stay retryable, 401/404/429 stay permanent). Revisits iteration-6's "per-step bounds exist, marginal gain, deprioritized" note — after the dial iteration proved the pattern, the two auth steps were the remaining members. Pinned by `wedged_login_aborts_at_the_sign_in_bound` (stalling server; elapsed ∈ [10s, 30s), retryable preserved).

19. **One teardown path, no exceptions** (`apply_auth_rejected` routes through `drop_socket`): the session-expiry teardown had bypassed `fail_jobs`, so in-flight RPC jobs lingered after an auth teardown until the 30s deadline sweep fired them with the misleading "The gateway did not answer in time." — the only teardown path that still had that latency, silently reintroduced alongside decision 16. Every teardown (socket close/fail, ready timeout, silence bound, write death, auth rejection) now fails in-flight jobs immediately with the accurate cause message. Audit lesson: after adding a new teardown entry point, mechanically compare it against the existing one — the auth path was written before the fail-jobs-at-teardown behavior existed (iteration 34 vs 35). Pinned by `auth_rejection_fails_in_flight_jobs_immediately` (job drained, one disconnect event, error names "Gateway session expired").

## Rejected with reasons (do not re-propose without new evidence)

- Cookie-reuse sign-in fast path (skip password-login when the session cookie is alive): no local evidence the gateway keeps the HTTP session across WS drops; wrong guess costs +1 RTT on every reconnect instead of saving one.
- Ping-timeout dead-link drop: an RPC error reply proves the link is alive; only total silence proves death, and the silence bound already covers it.
- Tightening `SILENCE_BOUND` below 90s: breaks the deliberate cover for a 90s server-side compress.
- Reqwest TCP `connect_timeout`: per-step sign-in bounds already exist via the 30s total request timeout.
